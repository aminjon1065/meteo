# Руководство администратора Метеопортала

Версия 1.0 · 17.10.2026 · Языки: [Тоҷикӣ](tg.md) · **Русский** · [English](en.md)

Для кого: администраторы, операторы мониторинга и редакторы Агентства по гидрометеорологии, работающие в административной панели Метеопортала (`/admin`). Эксплуатация серверов (развёртывание, резервные копии, обновления) описана отдельно в [Runbook для IT‑службы](../../runbook.md); работа с публичной частью портала — в [Руководстве пользователя](../user/ru.md).

Снимки экрана сделаны в русском интерфейсе; на таджикском и английском языках расположение элементов такое же, меняются только подписи.

## 1. Общие сведения

### 1.1. Адрес и вход

Панель открывается по адресу `https://<домен портала>/admin` (например, `https://portal.meteo.tj/admin`). Подходит любой современный браузер (Chrome, Firefox, Edge, Safari) на компьютере или планшете; на телефоне панель тоже работает, но для ввода данных удобнее экран шире 1024 px.

Учётные записи создаёт администратор в разделе «Пользователи» (см. [раздел 13](#13-пользователи)); самостоятельной регистрации нет. Пароль не короче 10 символов; его передают сотруднику по защищённому каналу.

### 1.2. Устройство панели

![Рис. 1. Дашборд: боковое меню, шапка с переключателем языка и темы, карточки состояния](../img/admin-dashboard.png)

- **Боковое меню** слева: группы «Измерения», «Контент», «Настройки». Разделы, недоступные вашей роли, в меню не показываются. Кнопка в левом верхнем углу сворачивает меню до иконок.
- **Шапка**: переключатель языка интерфейса (TG / RU / EN), светлая/тёмная тема и меню пользователя (имя, роль, пункт «Безопасность и 2FA», «Выйти»).
- Нижний пункт меню «Метеопортал» открывает публичный сайт.

Язык интерфейса панели не влияет на данные: все многоязычные поля (названия станций, тексты новостей, рекомендации) редактируются сразу на трёх языках через вкладки TG / RU / EN в форме.

### 1.3. Роли

| Что может | Администратор | Оператор | Редактор |
|---|---|---|---|
| Дашборд | ✓ | ✓ | ✓ |
| Реестр станций | создание, изменение, вывод из эксплуатации, ключ API | просмотр | просмотр |
| Измерения: ввод, импорт CSV, просмотр | ✓ | ✓ | — |
| Очередь контроля качества (решения) | ✓ | ✓ | — |
| Шкалы, пороги, ПДК (ПДКс.с./ПДКм.р.); медицинские рекомендации | ✓ | — | — |
| Правила уведомлений, события превышений, CAP‑сообщения, словарь событий | ✓ | — | — |
| Новости | ✓ | просмотр списка | создание, публикация |
| Медиафайлы, бюллетени | ✓ | — | ✓ |
| Подписчики, пользователи, журнал аудита, настройки | ✓ | — | — |

Проверка прав выполняется на сервере: даже если открыть адрес раздела напрямую, без нужной роли появится страница «Доступ запрещён».

## 2. Вход и двухфакторная аутентификация

### 2.1. Вход

![Рис. 2. Страница входа](../img/admin-login.png)

1. Откройте `/admin`, введите электронную почту и пароль, нажмите «Войти».
2. Если для учётной записи включена двухфакторная аутентификация (2FA), откроется запрос кода подтверждения.
3. После пяти неверных попыток входа за минуту сервер временно отклоняет запросы — подождите минуту.

Сессия действует 7 дней при регулярной работе; выход — через меню пользователя → «Выйти». После смены роли, сброса пароля или блокировки все сессии пользователя завершаются принудительно.

### 2.2. Обязательная 2FA для администраторов

Для роли «Администратор» 2FA обязательна: при первом входе без неё панель показывает только страницу настройки.

![Рис. 3. Первый вход администратора: требование включить 2FA](../img/admin-2fa-required.png)

Порядок включения:

1. Установите на телефон приложение‑аутентификатор (Google Authenticator, Microsoft Authenticator, Aegis, FreeOTP — любое приложение стандарта TOTP).
2. На странице «Двухфакторная аутентификация» введите пароль и нажмите «Включить 2FA».
3. Отсканируйте QR‑код приложением или введите ключ вручную.
4. **Сохраните резервные коды** (10 одноразовых кодов): нажмите «Скачать» или «Скопировать» и положите файл в менеджер паролей или сейф. Без телефона и без резервных кодов войти будет нельзя.
5. Введите шестизначный код из приложения и нажмите «Подтвердить и включить».

![Рис. 4. Мастер включения 2FA: QR‑код, ключ для ручного ввода, резервные коды и поле кода (ключ и коды на снимке скрыты)](../img/admin-2fa-scan.png)

### 2.3. Вход с кодом

![Рис. 5. Запрос кода подтверждения при входе](../img/admin-login-2fa.png)

- Введите код из приложения (обновляется каждые 30 секунд) и нажмите «Подтвердить».
- Если телефона нет под рукой — «Использовать резервный код». Каждый резервный код действует один раз.
- Флажок «Доверять этому устройству 30 дней» избавляет от ввода кода на этом компьютере в течение месяца. Не включайте его на общих компьютерах.
- После 10 неверных кодов учётная запись блокируется на 15 минут; ограничение — 5 попыток в минуту.
- Ошибка «Неверный или просроченный код» чаще всего означает, что на телефоне сбилось время: включите автоматическую синхронизацию времени.

### 2.4. Страница «Безопасность и 2FA»

Пункт меню пользователя → «Безопасность и 2FA» (`/admin/two-factor`): здесь видно состояние 2FA, можно выпустить новые резервные коды (старые перестают действовать; нужен пароль). Администратор не может отключить себе 2FA. Операторы и редакторы могут включить 2FA по желанию — рекомендуется.

![Рис. 6. Страница «Безопасность и 2FA» при включённой защите](../img/admin-two-factor-page.png)

Если телефон утерян и резервных кодов нет, другой администратор сбрасывает 2FA в разделе «Пользователи» (действие «Сбросить 2FA»); при следующем входе её нужно настроить заново. Если администратор один, восстановление доступа выполняет IT‑служба по runbook.

## 3. Дашборд

Дашборд (`/admin`) — сводка состояния системы (см. рис. 1):

| Блок | Что показывает | На что обратить внимание |
|---|---|---|
| Карточки | станций в реестре и активных, измерений за 24 часа, очередь контроля качества, активных превышений, пользователей | растущая очередь QC и превышения требуют реакции оператора |
| Свежесть данных по станциям | время последнего измерения каждой активной станции; «устарело» — нет данных за 24 часа; доля станций без данных | пост не передаёт данные — проверить ввод/импорт |
| Фоновый сервис | работает ли worker (heartbeat раз в минуту); «не отвечает» — обратиться в IT‑службу | без worker'а не обновляются индекс, прогнозы, письма |
| Очередь писем | настроен ли SMTP, сколько писем ожидают, с ошибками, отправлено за сутки; ссылка на тестовое письмо | ошибки отправки — проверить SMTP в «Настройках» |
| Интеграции | SmartMet (прогноз погоды), SILAM (прогноз качества воздуха), SmartMet Alert (CAP): последняя успешная загрузка, запуск модели, адрес источника, статус | статусы описаны в [разделе 14](#14-статусы-интеграций-и-фоновые-задачи) |
| Последние действия | последние записи журнала аудита | ссылка «Весь журнал» |

## 4. Реестр станций

Раздел «Станции» (`/admin/stations`) — паспорта постов и станций мониторинга воздуха. От записи в реестре зависят: отображение на карте и в списках портала, какие вещества можно вводить, единицы ввода, привязка к области для правил уведомлений.

![Рис. 7. Список станций с фильтрами по статусу и области](../img/admin-stations.png)

### 4.1. Добавление станции

Нажмите «Добавить станцию» и заполните форму.

![Рис. 8. Форма новой станции: основное, названия, расположение, эксплуатация, вещества](../img/admin-station-new.png)

| Поле | Как заполнять |
|---|---|
| Код | 2–32 символа: латиница, цифры, дефис, подчёркивание (например `DU-01`). Уникален; используется в файлах импорта и в API. Изменять после начала ввода данных не рекомендуется |
| Адрес (slug) | часть адреса страницы станции на портале; пусто — создаётся из названия |
| Название, описание, адрес | на трёх языках (вкладки TG / RU / EN); достаточно одного языка, остальные подставятся по цепочке tg → ru → en |
| Тип | воздух / метео / комбинированная |
| Статус | активна / приостановлена / выведена из эксплуатации |
| Широта, долгота | кликните по карте, перетащите маркер или введите вручную (широта 35–42, долгота 66–76) |
| Область, район | район выбирается после области; список районов заполняется из загруженных границ |
| Высота, м | необязательно |
| Введена в эксплуатацию | дата начала наблюдений |
| Источник данных | ручной ввод / импорт файлов / API / автоматический датчик — справочное поле |
| Режим отбора проб | разовые пробы (посты с отбором 3–4 раза в сутки) или непрерывный (автоматические датчики). От режима зависят строки времени по умолчанию в ручном вводе |
| Показывать на портале | снимите флажок, чтобы станция не появлялась на карте и в списках (данные при этом хранятся) |
| Измеряемые вещества | отметьте вещества и единицу входных данных (µg/m³, mg/m³, ppb, ppm). Хранение — всегда в единице вещества из справочника; значения пересчитываются при вводе |

«Сохранить» — откроется карточка созданной станции. Ошибка у поля «Код» означает, что такой код уже существует.

### 4.2. Карточка станции, ключ API, вывод из эксплуатации

![Рис. 9. Карточка существующей станции: форма, ключ API и вывод из эксплуатации](../img/admin-station-edit.png)

- Все поля редактируются так же, как при создании; изменения попадают в журнал аудита (до/после).
- **Ключ API станции** нужен для автоматической отправки измерений (агент станции, логгер или вендорское ПО → `POST /api/v1/ingest/{код}`). Ключ показывается один раз, в базе хранится только его хэш; «Обновить ключ» заменяет старый, и прежний перестаёт действовать сразу. Как подключить станцию — раздел 4.3.
- **Автоматический приём данных** (блок над формой): когда станция в последний раз присылала данные, по какому каналу (API или забор файлов), сколько записей принято и отклонено, период данных. Состояние «давно не было данных» означает, что приёма не было дольше порога (по умолчанию 3 часа).
- **Источники файлов (SFTP / FTP / HTTP)** (блок под формой): настройка забора файлов экспорта с сервера вендора — раздел 4.3.
- **Вывод из эксплуатации**: станция исчезает с портала, история измерений сохраняется и остаётся доступной в просмотре данных и API архива. Действие необратимо через интерфейс; при необходимости статус меняет IT‑служба.

### 4.3. Подключение станции: автоматический приём данных

Портал принимает данные со станций тремя способами; все они не зависят от производителя оборудования — формат файла или запроса описывается настройками.

| Способ | Когда подходит | Что настраивает администратор |
|---|---|---|
| Агент станции | ПО станции пишет файлы CSV/TSV в папку на станционном компьютере | ключ API в карточке; IT‑служба ставит агент на станцию (runbook, раздел 9.4) |
| Прямая отправка по API | логгер или ПО станции умеет отправлять запросы `POST /api/v1/ingest/{код}` | ключ API в карточке; описание формата — страница портала «API для разработчиков» (`/data/api`) |
| Забор файлов (SFTP / FTP / FTPS / HTTP) | данные уже выкладываются на сервер вендора или Агентства | источник в блоке «Источники файлов» карточки станции |
| JSON API сети датчиков | несколько датчиков отдают данные через один адрес в формате JSON — например, сеть PM‑датчиков Агентства (API wwcs.tj) | источник типа «JSON API» в блоке «Источники данных» карточки одной из станций; остальные станции получают данные по коду |

**Перед подключением** в карточке станции отметьте измеряемые вещества и единицы входных данных: значения по веществам, не отмеченным у станции, отклоняются с причиной `pollutantNotConfigured`. В поле «Источник данных» выберите «API» или «Автоматический датчик» — тогда дашборд и письма администраторам будут следить за перерывами в приёме.

**Ключ API** (блок «Ключ API станции»): «Сгенерировать ключ» → скопируйте ключ сразу, он больше не показывается. Передайте его IT‑службе для настройки агента или логгера. Если ключ мог попасть к посторонним — «Обновить ключ»: старый перестаёт действовать немедленно. Приостановка станции (статус «приостановлена») тоже закрывает приём (ответ 403).

**Источник файлов**: «Добавить источник» → заполните поля:

![Рис. 10. Форма «Добавить источник» в блоке «Источники файлов»: пример SFTP и шаблон описания колонок «столбец на вещество»](../img/admin-station-source-form.png)

| Поле | Как заполнять |
|---|---|
| Тип | SFTP (SSH), FTP, FTPS, HTTP(S) — файл по адресу, или «JSON API — сеть датчиков (несколько станций)» |
| Сервер, порт, пользователь, пароль | данные доступа к серверу вендора; пароль хранится зашифрованным и после сохранения не показывается (пустое поле при редактировании — оставить прежний, «-» — удалить). Вместо пароля можно указать `env:ИМЯ` — переменную окружения сервера портала (IT‑служба) |
| Приватный ключ SSH, отпечаток ключа сервера | для SFTP по ключу; отпечаток `SHA256:…` защищает от подмены сервера (пусто — без проверки) |
| Каталог на сервере, маска файлов | папка с экспортом и маска, например `*.csv` или `DU-01_*.txt`; для HTTP — полный адрес файла |
| Описание колонок (JSON) | формат файла: разделитель, кодировка, колонка времени и формат даты, колонки веществ (широкий формат) или колонки «вещество / значение / единица» (длинный формат). Кнопки шаблонов подставляют типовые описания — замените названия колонок на те, что в файле. Формат описания тот же, что в конфиге агента станции (`apps/station-agent/README.ru.md`) |
| Адрес JSON API, описание полей ответа (JSON) | для типа «JSON API»: адрес, по которому API отдаёт свежие записи всех станций, и описание полей — путь к массиву записей, поле кода станции (`stationField`; код в ответе должен совпадать с кодом станции портала или задаётся в `stations`), поле времени с часовым поясом, поля веществ и единицы, период осреднения (`averagingMin`), при наличии — адрес ряда за прошедшие часы (`history`) для догрузки пропусков. Шаблон «JSON API (wwcs.tj)» уже подходит для сети датчиков Агентства |
| Уведомить, если нет данных дольше, мин | через сколько минут без принятых значений администраторы получат письмо (по умолчанию 180) |
| Включён | выключенный источник не опрашивается, настройки сохраняются |

После сохранения нажмите «Проверить сейчас»: через минуту в строке источника появятся статус («работает» / «сбой» с текстом ошибки), время последнего запуска, успеха и данных и сводка последнего запуска (файлов, принято, отклонено, первые ошибки с номерами строк). Дальше портал забирает новые и изменившиеся файлы каждые 10 минут; повторная обработка файла безопасна — значения обновляются по ключу «время + вещество», решения оператора в очереди контроля качества не перезаписываются.

**Сеть PM‑датчиков Агентства (API wwcs.tj).** Девять датчиков PM2.5/PM10 (шесть в Душанбе, Куляб, Вахдат, Гиссар) заводит скриптом IT‑служба (runbook, раздел 9.4): станции появляются в реестре с названиями на трёх языках, координатами и веществами, а в карточке станции «Ул. Шукуфон, 59 (Медгородок)» (DYU01_ECO) создаётся источник «JSON API» «WWCS airquality API» — основной канал данных этой сети, уже включённый: портал забирает историю за сутки и дальше опрашивает API каждые 10 минут; «Проверить сейчас» запускает внеочередной опрос, переключатель «Включён» останавливает его без удаления настроек. Данные приходят на все девять станций по коду датчика; у станций без своего источника они видны в блоке «Автоматический приём данных» (канал «забор данных»). Станция «Агентство по гидрометеорологии» (DYU006_ECO) создана **приостановленной**: её датчик показывает сотни мкг/м³ при нормальном фоне у соседей, и автоматические правила контроля такие значения не отбраковывают — снимите приостановку в карточке после ремонта датчика. Повторные ответы API не создают дублей: по каждой станции хранится время последней принятой записи, поэтому «зависший» датчик через час даёт письмо «нет данных», а его индекс через 6 часов становится «нет данных».

**Как проверить, что данные идут**: блок «Автоматический приём данных» в карточке (время и канал последнего приёма, принято/отклонено), колонка «Автоматический приём» на дашборде (раздел 3), записи `measurements.ingest` и `measurements.pull` от имени `station:<код>` в журнале аудита (раздел 6). Отклонённые записи не теряются молча: причина по каждой (`unknownPollutant`, `unit`, `time`, `futureTime` …) возвращается отправителю и попадает в сводку источника.

![Рис. 11. Блок «Автоматический приём данных» после первого приёма по API: состояние, время и канал последнего приёма, принято/отклонено, период данных и версия агента](../img/admin-station-ingest.png)

![Рис. 12. Дашборд: колонка «Автоматический приём» в таблице «Свежесть данных по станциям» и счётчик станций без приёма дольше порога](../img/admin-dashboard-ingest.png)

**Письма администраторам**: если источник не принёс ни одного значения дольше своего порога или станция с приёмом по API молчит дольше 3 часов, всем администраторам (и адресам из `ADMIN_ALERT_EMAILS`) уходит письмо «Нет данных со станции…», при возобновлении — «Данные снова поступают».

## 5. Измерения

Раздел «Измерения» (`/admin/measurements`) объединяет ручной ввод, импорт CSV, просмотр данных и очередь контроля качества; внизу — последние пакеты импорта.

![Рис. 13. Раздел «Измерения»](../img/admin-measurements.png)

### 5.1. Ручной ввод

Для постов с разовыми пробами и лабораторных данных.

![Рис. 14. Ручной ввод: сетка время × вещество за выбранную дату](../img/admin-entry.png)

1. Выберите станцию и дату (местное время, Душанбе). В сетке появляются только вещества, отмеченные у станции, с её единицами ввода.
2. Строки времени по умолчанию зависят от режима станции (для разовых проб — 01:00, 07:00, 13:00, 19:00); время можно изменить, строки — добавить или удалить (до 48 строк).
3. Введите значения. Десятичный разделитель — точка или запятая. Можно вставить строку из Excel: значения через табуляцию или точку с запятой.
4. «Сохранить измерения». Внизу появится сообщение «Сохранено значений: N».

Что происходит при сохранении:

- значения пересчитываются в единицу вещества (например, ppb → µg/m³ по молярной массе);
- проверяется правило диапазона: значение вне допустимого интервала сохраняется с флагом «недостоверное» и попадает в очередь контроля качества; остальные получают флаг «валидное»;
- повторный ввод за то же время, станцию и вещество заменяет старое значение (с записью в аудит);
- индекс станции пересчитывается сразу, портал обновляется в течение минуты.

### 5.2. Импорт CSV

Для файлов с постов, из лабораторной информационной системы или с автоматических датчиков. Импорт идёт в два шага: сначала проверка, потом запись.

![Рис. 15. Импорт CSV, шаг 1: выбор файла и станции по умолчанию](../img/admin-import-step1.png)

Формат файла:

- столбцы `time`, `station`, `pollutant`, `value`, `unit` (единица необязательна); заголовки допускаются и по‑русски (`время`, `станция`, `вещество`, `значение`, `единица`);
- разделитель столбцов — запятая, точка с запятой или табуляция (определяется автоматически); кодировка UTF‑8 (Excel: «CSV UTF‑8»);
- время — ISO 8601 (`2026-10-17T07:00:00+05:00`) или `ГГГГ-ММ-ДД ЧЧ:ММ` по времени Душанбе; время в будущем отклоняется;
- `station` — код станции из реестра; если столбца нет, выберите «Станцию по умолчанию»;
- `pollutant` — код вещества: `PM25`, `PM10`, `NO2`, `SO2`, `CO`, `O3`;
- `value` — число с точкой или запятой; `unit` — `ug/m3`, `µg/m³`, `мкг/м3`, `mg/m3`, `ppb`, `ppm` (пусто — единица ввода станции);
- до 100 000 строк и 20 МБ в одном файле; дубликаты строк (время + станция + вещество) внутри файла отклоняются.

Шаблон с правильными заголовками — ссылка «Скачать шаблон CSV». Учебный файл можно сгенерировать командой из материалов обучения (`node docs/training/make-sample-csv.mjs`).

![Рис. 16. Импорт CSV, шаг 2: отчёт проверки и кнопки «Применить» / «Отклонить»](../img/admin-import-report.png)

После «Проверить файл» показывается отчёт: строк в файле, корректных, отклонённых (с номером строки и причиной), вне диапазона. «Применить (N)» записывает корректные строки; строки с ошибками пропускаются — исправьте их в файле и загрузите отдельно. «Отклонить» удаляет пакет без записи. Пакет проверки хранится ограниченное время: если появилось сообщение «Срок проверки истёк», загрузите файл заново.

Значения вне диапазона записываются с флагом «недостоверное» и ждут решения в очереди QC. Индекс пересчитывается после применения. Повторный импорт того же файла безопасен: значения с тем же временем, станцией и веществом обновляются.

### 5.3. Просмотр данных

![Рис. 17. Просмотр данных: фильтры по станции, веществу и периоду](../img/admin-browse.png)

Фильтры: станция, вещество, период. В таблице — время (местное), значение в единице вещества, осреднение (20 — разовая проба, 60 — час, 1440 — сутки), флаг контроля качества, источник (ручной ввод / импорт / API / датчик). Флаги:

| Флаг | Значение | Учитывается в индексе и графиках |
|---|---|---|
| Сырое | получено, автоматический контроль ещё не прошёл | да (до решения) |
| Валидное | прошло контроль или подтверждено оператором | да |
| Подозрительное | автоматический контроль отметил аномалию, ждёт решения | нет |
| Недостоверное | вне диапазона или отклонено оператором | нет |
| Скорректировано | значение исправлено оператором, исходное сохранено | да (новое значение) |
| Нет данных | пропуск | нет |

### 5.4. Очередь контроля качества

Автоматический контроль качества (QC) выполняется фоновым сервисом каждые 15 минут и при вводе:

| Правило | Что ловит |
|---|---|
| Диапазон (при вводе и импорте) | значение вне физически допустимого интервала для вещества → «недостоверное» |
| Скачок | резкое отличие от соседних по времени значений → «подозрительное» |
| Залипание датчика | одно и то же значение много часов подряд → «подозрительное» |
| Выброс относительно истории станции | робастный критерий (MAD) по истории станции → «подозрительное» |

![Рис. 18. Очередь контроля качества](../img/admin-qc.png)

Решение оператора по каждому значению:

- **Подтвердить** — значение верное; флаг «валидное», значение участвует в расчётах.
- **Исправить** — ввести новое значение и причину (например, «ошибка ввода: лишний ноль»); исходное значение сохраняется, флаг «скорректировано».
- **Отклонить** — исключить из расчётов и графиков; флаг «недостоверное».

![Рис. 19. Диалог исправления значения с указанием причины](../img/admin-qc-correct.png)

После решения значение блокируется для автоматического контроля (повторно в очередь не попадёт), индекс станции пересчитывается, в журнал аудита пишется действие с «до → после» и причиной. Фильтр «Решение → Уже обработаны» показывает историю решений.

## 6. Журнал аудита

Раздел «Журнал аудита» (`/admin/audit`) хранит все действия в панели: кто (e‑mail и роль), когда, что сделал (`stations.update`, `measurement.correct`, `news.publish`, `user.ban` и т. п.), с каким объектом, и состояние «до» / «после» в виде JSON. Записи нельзя изменить или удалить — даже администратору; при удалении пользователя его действия остаются в журнале с e‑mail.

![Рис. 20. Журнал аудита с фильтрами по объекту, периоду и поиском](../img/admin-audit.png)

Поиск по действию, e‑mail или идентификатору; фильтр по объекту и периоду. Используйте журнал при разборе спорных значений, восстановлении случайно изменённых настроек и проверках.

## 7. Шкалы, пороги и ПДК

Раздел «Шкалы и пороги» (`/admin/scales`) — только для администраторов. Изменения применяются к расчёту индекса сразу и влияют на весь портал, виджеты и API; меняйте пороги только по утверждённой методике и фиксируйте решение документально.

![Рис. 21. Список шкал индекса](../img/admin-scales.png)

В поставке три шкалы:

| Шкала | Тип | Назначение |
|---|---|---|
| Оперативный индекс качества воздуха | интервальная (5 уровней по часовым концентрациям, худшее вещество) | публичная шкала по умолчанию: карта, страницы станций, виджеты |
| Шкала по рекомендациям ВОЗ | интервальная (среднесуточные нормативы ВОЗ 2021) | справочная |
| Индекс загрязнения атмосферы (ИЗА) | комплексный по среднемесячным концентрациям и ПДК | национальная отчётность |

### 7.1. Редактирование шкалы

![Рис. 22. Карточка шкалы: основное, уровни, пороги по веществам](../img/admin-scale-edit.png)

- **Основное**: название и описание на трёх языках, флажки «Включена» и «Публичная шкала по умолчанию» (ровно одна шкала может быть публичной), порядок.
- **Уровни**: подписи пяти уровней на трёх языках; цвета заданы дизайн‑системой (зелёный, жёлтый, оранжевый, красный, фиолетовый) и не меняются.
- **Пороги по веществам** (интервальная шкала): нижняя граница каждого уровня в единице вещества и период осреднения (1 ч, 8 ч, 24 ч). Границы должны строго возрастать; для вещества нужно заполнить все пять границ либо оставить строку пустой — тогда вещество в индекс не входит.

После «Сохранить» появится сообщение «Шкала сохранена, индекс пересчитан».

### 7.2. ПДК и классы опасности

![Рис. 23. Таблица ПДК и классов опасности](../img/admin-limits.png)

Страница «ПДК и классы опасности» (`/admin/scales/limits`): среднесуточные (ПДКс.с.), максимальные разовые (ПДКм.р.) и среднегодовые (ПДКс.г.) ПДК в единице вещества, а также класс опасности (1–4) для расчёта ИЗА. Пустое поле — норматив не задан. Значения по умолчанию — таблица норм ежедневного бюллетеня Агентства о загрязнении атмосферного воздуха (19.10.2026; мг/м³ переведены в единицу вещества): PM2.5 35/160, PM10 60/300, NO₂ 40/85, SO₂ 50/500, CO 3/5 mg/m³, O₃ 30/160, NO 60/400, формальдегид 3/35, фенол 3/10, HF 5/20, пыль 150/500 µg/m³, ЛОС 300/900 ppb; у CO₂ норматива нет. Значения, изменённые здесь, при обновлениях портала не перезаписываются. По ПДКс.с. и ПДКм.р. портал считает кратности по методике Агентства (шкала «Кратность ПДК»): суммацию NO₂+SO₂ и случаи ВЗ/ЭВЗ — см. страницу станции и `/air/index`.

## 8. Медицинские рекомендации

Раздел «Медицинские рекомендации» (`/admin/health-advice`) — тексты, которые портал показывает рядом с индексом: на главной, на страницах станций, в разделе «Здоровье» и в виджетах.

![Рис. 24. Матрица рекомендаций: уровень × группа населения × язык](../img/admin-health-advice.png)

- Выберите шкалу (обычно — публичную по умолчанию).
- Для каждого уровня (1–5) и каждой группы населения (общее население, дети, беременные и кормящие, пожилые, хронические респираторные заболевания, сердечно‑сосудистые заболевания) заполните заголовок и текст на трёх языках.
- Сохраняйте по кнопке «Сохранить уровень «…»» под каждым уровнем.

Тексты должны быть согласованы с медицинскими экспертами; на портале рядом с ними выводится оговорка, что рекомендации не заменяют консультацию врача.

## 9. Уведомления о превышениях и подписчики

### 9.1. Правила уведомлений

Раздел «Уведомления» (`/admin/alerts`): правила, по которым портал показывает баннер превышения и отправляет письма подписчикам.

![Рис. 25. Список правил уведомлений](../img/admin-alerts.png)

![Рис. 26. Форма правила: условие, область действия, доставка](../img/admin-alert-new.png)

| Поле | Описание |
|---|---|
| Название | как правило будет называться в баннере и письмах |
| Тип условия | концентрация вещества (порог в единице вещества, сравнение «больше или равно» со средним за период осреднения 1 / 8 / 24 ч) или уровень индекса (порог 1–5 по выбранной шкале) |
| Область действия | все станции / одна станция / область |
| Каналы | «Портал» — баннер на главной и странице станции, данные в `/api/v1/exceedances`; «E‑mail» — письма подтверждённым подписчикам станции или всех станций |
| Пауза между событиями, мин | после закрытия события новое по тому же правилу и станции не откроется раньше этого времени (0–10080) |
| Правило включено | выключенное правило сохраняется, но не проверяется |

Как работает проверка: фоновая задача каждые 10 минут берёт последний доступный час данных каждой станции (не старше 6 часов), сравнивает с порогом, открывает событие превышения, обновляет пиковое значение и закрывает событие, когда значение опускается ниже порога. Письма ставятся в очередь один раз на событие и подписчика.

### 9.2. События превышений

![Рис. 27. События превышений: активные и завершённые](../img/admin-alert-events.png)

Страница «События превышений» (`/admin/alerts/events`): начало, окончание, пик, были ли отправлены письма. Активное событие можно закрыть вручную кнопкой «Закрыть» (например, после отклонения ошибочного значения в QC).

### 9.3. Подписчики

![Рис. 28. Подписчики: статусы, темы, экспорт](../img/admin-subscribers.png)

Раздел «Подписчики» (`/admin/subscribers`) показывает адреса, язык, статус (подтверждено / ожидают / отписались) и темы: все станции, выбранные станции, информационный бюллетень. Подписка оформляется посетителями на странице `/subscribe` с подтверждением по ссылке из письма (double opt‑in); отписка — по ссылке в каждом письме. Редактировать адреса в панели нельзя — это защищает от рассылки без согласия. «Экспорт CSV» выгружает список для отчётности; обращайтесь с ним как с персональными данными.

## 10. CAP‑предупреждения

Раздел «CAP‑сообщения» (`/admin/cap`) — штормовые предупреждения из редактора SmartMet Alert в формате CAP 1.2. Портал сам их не создаёт: фоновая задача каждые 5 минут читает фид (адрес задаёт IT‑служба переменной `CAP_FEED_URL`) и сохраняет сообщения; на портале они появляются в разделе «Предупреждения», на карте, на главной, в виджете и в API.

![Рис. 29. Список CAP‑сообщений со статусом синхронизации](../img/admin-cap.png)

Статусы в списке:

| Статус | Значение |
|---|---|
| публикуется | действующее или ожидаемое сообщение, видно на портале |
| истекло | срок действия (`expires`) прошёл — с портала скрыто, в архиве панели остаётся |
| заменено | пришло сообщение типа Update со ссылкой на это; показывается новая версия |
| отменено | пришло сообщение Cancel; с портала снято |
| не публикуется | статус `Test`, `Exercise`, `Draft` — видно только в панели |

Блок «Синхронизация» вверху показывает результат последнего запуска (успешно / частично / ошибка / без изменений / источник не настроен) и ошибки разбора отдельных файлов.

![Рис. 30. Карточка CAP‑сообщения: блоки info по языкам, области, параметры, исходный XML](../img/admin-cap-detail.png)

В карточке сообщения — все блоки `info` (по языкам), области действия с привязкой к регионам предупреждений, параметры и кнопка «XML» для исходного файла. Это помогает разобраться, почему сообщение отображается не так, как ожидалось (например, нет блока на таджикском — используется фолбэк и словарь событий).

### 10.1. Словарь событий

![Рис. 31. Словарь типов событий CAP](../img/admin-cap-events.png)

Страница «Типы событий» (`/admin/cap/events`): переводы поля `event` (например, `Strong wind` → «Сильный ветер» / «Шамоли сахт») на три языка. Они используются, когда сообщение не содержит блока `info` на языке портала. Новые типы событий появляются в словаре автоматически после первой синхронизации — заполните переводы, иначе на портале будет показан исходный текст из сообщения.

| Текст | Markdown: заголовки `#`, списки, `**жирный**`, `*курсив*`, `[ссылка](https://…)`, `![картинка](/uploads/…)`; HTML‑теги не пропускаются. Вкладка «Предпросмотр» показывает результат |
| Адрес (slug) | общий для всех языков; пусто — из заголовка |
| Рубрика | из справочника (страница «Рубрики») |
| Обложка | изображение JPEG, PNG, WebP или GIF до 10 МБ; загружается прямо из формы или выбирается из медиафайлов |
| Статус | черновик → опубликовано → в архиве. Черновики на портале не видны |
| Дата публикации | пусто — момент публикации; будущая дата — отложенная публикация (новость появится в указанное время) |
| Закрепить на главной | закреплённая новость показывается первой |

Кнопка «Опубликовать» / «Снять с публикации» меняет статус без повторного сохранения формы. «Открыть на портале» ведёт на страницу новости. Рубрики управляются на странице «Рубрики» (название на трёх языках, slug, порядок).

### 11.3. Бюллетени

![Рис. 36. Список бюллетеней](../img/admin-bulletins.png)

![Рис. 37. Новый бюллетень: тема и текст на трёх языках, связанная новость](../img/admin-bulletin-new.png)

Раздел «Бюллетени» (`/admin/bulletins`) — рассылка подписчикам, выбравшим информационный бюллетень.

1. Создайте бюллетень: тема и текст письма (Markdown) на языках подписчиков; при желании свяжите с новостью — в письмо добавится ссылка.
2. Сохраните и проверьте «Предпросмотр письма».
3. «Отправить подписчикам»: панель покажет число получателей; после подтверждения письма ставятся в очередь, каждому — на языке его подписки, со ссылкой на отписку. Отменить рассылку после запуска нельзя.
4. Статус меняется на «В очереди», затем на «Отправлен», когда фоновый сервис отправит все письма (обычно в течение нескольких минут). Отправленный бюллетень изменить нельзя.

Если на дашборде в очереди писем растут ошибки, рассылка не уходит — проверьте SMTP в «Настройках» и обратитесь в IT‑службу.

### 11.4. Экобюллетень

Раздел «Экобюллетень» (`/admin/eco-bulletins`) готовит ежедневный экологический бюллетень в формате Агентства —
три документа на таджикском и русском языках: бюллетень города («Экологический бюллетень г. Душанбе» /
«Шарҳи ҳолати ифлосшавии ҳаво»), сводку по городам республики («Загрязнение атмосферного воздуха» / «ИҲА») и
форму 4а («Намунаи 4а», превышения ПДК по городам). Доступен администратору, оператору и редактору.

**Как это считается.** За местные сутки (00:00–24:00 по Душанбе) по валидным измерениям (флаги QC «валидно» и
«скорректировано») для каждого вещества станции берутся среднесуточная и максимальная разовая концентрации (в
документах — мг/м³), кратности к ПДКс.с. и ПДКм.р. из раздела «Шкалы и пороги → ПДК», число случаев превышения
(> ПДК и ≥ 5 ПДК), суммация NO2+SO2 (по методике Агентства — сумма отношений среднесуточных концентраций к ПДКм.р.),
сравнение кратностей с предыдущими сутками («повышение / понижение / на уровне») и признаки ВЗ (разовое значение
≥ 10 ПДКм.р.) и ЭВЗ (≥ 50 ПДКм.р.). Сводка по городам объединяет публичные станции по городам (Душанбе; города —
по району станции; иначе область); для города выбранной станции берутся её данные. Вещества в ppm/ppb (CO2, ЛОС)
печатаются без кратностей.

**Порядок работы.**

1. В форме «Новый бюллетень» выберите дату (по умолчанию — вчера) и станцию города (автоматическая станция
   Душанбе) → «Сформировать». Откроется страница бюллетеня с предпросмотром; повторное формирование за ту же
   дату и станцию пересчитывает существующий черновик.
2. Проверьте предупреждения над документом: «нет данных за сутки», «нет данных за предыдущие сутки» (сравнение
   не выполнено), «нет данных по веществам: …». Кнопка «Пересчитать по данным» обновляет черновик после ввода или
   корректировки измерений.
3. Переключайте документ (бюллетень города / сводка по городам / форма 4а) и язык (тоҷикӣ / русский); справа —
   итоги расчёта: превышения, суммация, число городов, ВЗ/ЭВЗ.
4. Введите радиационный γ‑фон (например, `0,014`) и нажмите «Сохранить» — абзац о гамма‑фоне появится в документе;
   без значения абзац не печатается.
5. Скачайте документы: **DOCX** (Word, Times New Roman, A4 — структура как у образцов Агентства), **PDF**
   (если на сервере установлен Chromium; иначе откроется печатная версия — сохраните её как PDF из диалога печати)
   или **HTML**.
6. «Опубликовать»: файлы сохраняются в архиве портала («Экобюллетени», `/air/bulletins`), создаётся опубликованная
   новость рубрики «Бюллетени» с кратким текстом и ссылками на файлы; флажок «Разослать подписчикам» ставит
   письма подписчикам информационного бюллетеня. Опубликованный бюллетень изменить нельзя; черновик можно
   удалить.

**Автоматический черновик.** Фоновый сервис ежедневно в 08:00 по Душанбе готовит черновик за прошедшие сутки по
станциям из настроек (по умолчанию — все публичные автоматические станции) и отправляет операторам и
администраторам одно письмо «Черновики экобюллетеня за … готовы» со списком станций, превышений и ссылками. Оператору остаётся проверить данные,
указать γ‑фон и опубликовать.

**Настройки** (кнопка «Настройки» в разделе): включение расписания и уведомлений, станции для автоматического
черновика, подпись отдела (по умолчанию «ОИ УМОС» / «ШИ РММЗ»), фраза о причинах превышений («из‑за
метеорологических условий и антропогенных факторов …») и метод суммации NO2+SO2. Остальные формулировки
(заголовки, шапки таблиц, примечания с расшифровкой сокращений, названия веществ) — в файле шаблонов
`packages/core/src/bulletin-phrases.ts`, который меняет IT‑служба.

Все действия (формирование, пересчёт, γ‑фон, публикация, удаление, настройки) записываются в журнал аудита.

## 12. Настройки

Раздел «Настройки» (`/admin/settings`) — только для администраторов.

![Рис. 38. Настройки: проверка SMTP, адреса интеграций, брендинг](../img/admin-settings.png)

- **Почта (SMTP)**: показывает, настроен ли SMTP (параметр `SMTP_URL` задаётся на сервере). «Отправить тестовое письмо» ставит письмо в очередь и показывает его статус (в очереди → отправлено / ошибка с текстом). Тест проверяет весь путь: очередь → SMTP → ящик. Без `SMTP_URL` письма только записываются в журнал фонового сервиса — режим разработки.
- **Адреса интеграций**: SmartMet, SILAM, SmartMet Alert, адрес портала — только для просмотра; учётные данные скрыты. Изменить их может только IT‑служба через переменные окружения (см. runbook).
- **Единицы отображения**: единица массовых концентраций на страницах станций, главной, в виджетах, API и CSV — «µg/m³ (CO — mg/m³)» по умолчанию или «mg/m³ как в бюллетенях Агентства». Данные хранятся в единице вещества и пересчитываются при выводе (при переводе в mg/m³ показывается на три знака больше); ppm (CO₂) и ppb (ЛОС) не меняются. Применяется в течение минуты.
- **Брендинг**: название портала, название организации, e‑mail, телефон, адрес, сайт, дополнительная строка подвала — на трёх языках. Показываются в шапке, подвале и на странице «О портале» в течение минуты после сохранения.

## 14. Статусы интеграций и фоновые задачи

Фоновый сервис (worker) выполняет задачи по расписанию; их состояние видно на дашборде, а детали — в журналах сервера (IT‑служба).

| Задача | Расписание | Что делает |
|---|---|---|
| Пересчёт индекса | каждые 10 минут и после ввода/импорта | индекс станций по всем включённым шкалам за последние часы |
| Контроль качества | каждые 15 минут | правила скачка, залипания, выбросов → очередь QC |
| Проверка порогов | каждые 10 минут | события превышений и письма по правилам уведомлений |
| Отправка писем | каждую минуту | очередь писем → SMTP (подтверждения подписки, уведомления, бюллетени, служебные письма) |
| SmartMet (прогноз погоды) | каждые 15 минут | почасовой и суточный прогноз для точек прогноза |
| SILAM (прогноз качества воздуха) | каждый час (в :20) | новый прогон модели: слои для карты и точечные прогнозы для городов и станций |
| SmartMet Alert (CAP) | каждые 5 минут | новые, обновлённые и отменённые предупреждения |

Статусы интеграций на дашборде:

| Статус | Значение | Действие |
|---|---|---|
| актуально | последняя загрузка прошла успешно и недавно | — |
| устарело | загрузка давно не выполнялась; на портале появляется пометка «устарело» | проверить фоновый сервис и источник |
| сбой, подряд: N | источник отвечает ошибкой | после 3 сбоев подряд администраторы получают письмо; подождать или сообщить IT‑службе |
| приостановлено до … | после серии сбоев запросы к источнику временно остановлены (защитный «предохранитель»); возобновятся автоматически через 30–240 минут | если источник уже восстановлен, IT‑служба может запустить задачу вручную |
| источник не настроен | адрес источника не задан (например, `CAP_FEED_URL`) | задать переменную окружения (runbook) |
| ещё не выполнялась | сервис только запущен | подождать |

Письма администраторам о сбоях и восстановлении приходят на адреса всех пользователей с ролью «Администратор» и на дополнительные адреса из настроек сервера.

## 15. Частые ошибки и вопросы

| Ситуация | Причина | Что делать |
|---|---|---|
| «Доступ запрещён» при открытии раздела | роль не даёт прав | обратиться к администратору для смены роли |
| «Неверный или просроченный код» при входе | расходится время на телефоне; код введён после смены | включить автоматическое время на телефоне, ввести свежий код |
| «Слишком много попыток» | лимит 5 попыток в минуту или блокировка после 10 неверных кодов | подождать 1–15 минут |
| Телефон с приложением утерян | нет второго фактора | использовать резервный код; иначе другой администратор → «Сбросить 2FA» |
| Файл CSV не проходит проверку: «Нет обязательного столбца» | заголовки не распознаны | проверить названия столбцов, скачать шаблон |
| «Неизвестная станция» в отчёте импорта | код в файле не совпадает с кодом в реестре | исправить код или выбрать станцию по умолчанию |
| «Время в будущем» / «Некорректное время» | формат даты или часовой пояс | использовать `ГГГГ-ММ-ДД ЧЧ:ММ` по Душанбе или ISO 8601 с `+05:00` |
| «Неизвестная единица» | единица написана нестандартно | `ug/m3`, `mg/m3`, `ppb`, `ppm` или пусто |
| После ввода индекс «нет данных» | значения с флагом «подозрительное» или «недостоверное» не участвуют; или данные старше 6 часов | решить значения в очереди QC; проверить время измерений |
| На дашборде станция «устарело» | нет данных за 24 часа | ввести или импортировать данные |
| Станции нет на карте | снят флажок «Показывать на портале» или статус не «активна»; нет координат | проверить карточку станции |
| Новость не видна на портале | статус «черновик» или дата публикации в будущем | опубликовать или проверить дату |
| Письма не уходят, в очереди ошибки | SMTP не настроен или недоступен | проверить тестовым письмом; сообщить IT‑службе |
| Предупреждения CAP не обновляются | источник не настроен, недоступен или сообщения с ошибками | посмотреть блок «Синхронизация» в разделе CAP; сообщить IT‑службе |
| Прогноз «устарел» на портале | синхронизация SmartMet/SILAM давно не выполнялась | статус интеграций на дашборде; IT‑служба |
| «Нельзя: это последний активный администратор» | защита от потери доступа | сначала создать второго администратора |
| Забыл пароль | — | администратор → «Сбросить пароль» |
