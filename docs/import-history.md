# Импорт исторических данных измерений (CSV / XLSX)

Скрипт `packages/db/src/scripts/import-history.ts` загружает архивы измерений Агентства в таблицу
`measurements` по описанию колонок (маппингу) без изменения кода. Поддерживаются CSV (любая
кодировка, поддерживаемая Node — `utf-8`, `windows-1251`, разделитель определяется автоматически)
и XLSX (первый или указанный лист). Повторный импорт того же файла безопасен: значения с тем же
ключом (время, станция, вещество, период осреднения) обновляются, а не дублируются.

## Запуск

```bash
# проверка маппинга без записи: отчёт по строкам, ничего не пишется
pnpm --filter @meteo/db import-history -- --file ~/data/du-01-2023.csv --mapping mapping.json --dry-run

# первые 200 строк, отчёт в JSON
pnpm --filter @meteo/db import-history -- -f archive.xlsx -m mapping.json --sheet "2023" --limit 200 --report report.json

# импорт
pnpm --filter @meteo/db import-history -- -f archive.xlsx -m mapping.json
```

Через корневой каталог: `pnpm db:import-history -- …`. В продакшене скрипт запускается из клона
репозитория на сервере (`pnpm install`, затем `pnpm db:import-history -- …` с `DATABASE_URL` из `.env`)
или с рабочей станции через SSH-туннель к PostgreSQL — см. `docs/runbook.md`, раздел «Импорт архивов».

| Параметр | Назначение |
|---|---|
| `--file`, `-f` | путь к CSV/XLSX |
| `--mapping`, `-m` | JSON-маппинг (ниже) |
| `--station CODE` | код станции, если в файле нет столбца станции (заменяет `station` маппинга) |
| `--sheet NAME` или `N` | лист XLSX (имя или номер с 0) |
| `--dry-run` | только разбор и отчёт |
| `--limit N` | обработать N первых строк |
| `--report path` | записать `{summary, errors[]}` в JSON |
| `--no-index` | не пересчитывать индекс (например, при серии импортов — пересчитать один раз из worker) |
| `--batch-size N` | размер пачки вставки (1000) |

Что происходит при импорте:

1. Файл читается целиком (CSV до ~100 МБ, XLSX до ~50 МБ — для больших архивов разбейте по годам).
2. Для каждой строки: станция по коду (регистр не важен) → время в UTC → значения веществ:
   пропуски (`missingValues`), десятичная запятая, значения «ниже предела обнаружения» (`<5` →
   половина предела, `qc_reason = belowDetectionLimit:5`), единицы (`ppb`/`ppm`/`mg/m³` → единица
   справочника; для газов используется молярная масса), проверка диапазона правил QC (вне диапазона
   → флаг `invalid`, значение сохраняется).
3. Принятые значения получают `qc_flag` из маппинга (`1` valid — для выверенных архивов, `0` raw —
   пройдут автоматический контроль качества worker'а), `source = import`, `batch_id` пакета.
4. Создаётся запись `import_batches` (файл, число строк, ошибки) и запись аудита
   `measurements.importHistory`; индекс станций пересчитывается по месяцам затронутого периода.

Отчёт в консоли: число строк, принятых/отклонённых значений, дубликатов (внутри файла — берётся
первое), значений вне диапазона, период данных, первые 20 ошибок (`строка N: тип:деталь`).

## Маппинг

```jsonc
{
  "layout": "wide",                       // "wide" — столбец на вещество; "long" — вещество/значение в строке
  "sheet": "2023",                        // XLSX: имя или индекс листа (по умолчанию первый)
  "headerRow": 1,                         // строка заголовка (с 1); строки выше пропускаются
  "delimiter": ";",                       // CSV; без значения — автоопределение (; , табуляция |)
  "encoding": "windows-1251",             // CSV; по умолчанию utf-8
  "station": { "column": "Пост" },        // или { "value": "DU-01" } — одна станция на файл
  "time": {                               // вариант 1: одна колонка
    "column": "Дата и время",
    "format": "DD.MM.YYYY HH:mm",         // токены YYYY YY MM M DD D HH H mm m ss s; без формата —
    "timezone": "Asia/Dushanbe"           //   ISO / DD.MM.YYYY HH:mm / серийная дата Excel
  },
  // "time": { "dateColumn": "Дата", "timeColumn": "Срок", "format": "DD.MM.YYYY", "timeFormat": "HH:mm", "defaultTime": "13:00" },
  "averagingMin": 20,                     // период осреднения; без значения — 60 для непрерывных станций, 20 для разовых проб
  "pollutants": {                         // wide: ключ — код вещества или синоним из pollutantAliases
    "PM25": { "column": "PM2,5 мкг/м3" },
    "NO2": { "column": "NO2 мг/м3", "unit": "mg/m3", "scale": 1 }
  },
  "pollutantColumn": "parameter",         // long
  "valueColumn": "value",
  "unitColumn": "unit",                   // необязательно; иначе defaultUnit → единица станции → единица вещества
  "defaultUnit": "µg/m³",
  "pollutantAliases": { "Диоксид азота": "NO2", "pm2.5": "PM25" },
  "missingValues": ["", "-", "н/д"],
  "qcFlag": 1                             // 1 valid (по умолчанию) или 0 raw
}
```

Колонки задаются именем заголовка (регистр и лишние пробелы не важны) или индексом с 0.
Часовой пояс: `Asia/Dushanbe` (UTC+5, без перехода на летнее время — по умолчанию), `UTC` или
смещение `+05:00`; ISO-строки со своей зоной (`…+05:00`, `…Z`) берутся как есть. Даты из XLSX,
отформатированные как дата, распознаются автоматически (числовые серийные даты Excel тоже).

Примеры маппингов и тестовый CSV — `infra/data/import/`. Логика разбора — чистые модули
`@meteo/core` (`import-mapping.ts`, `csv.ts`, `xlsx.ts`) с тестами; скрипт только читает файл,
справочники и пишет в БД.

## Типичные ошибки отчёта

| Сообщение | Причина и действие |
|---|---|
| `unknownStation:XX-01` | кода нет в реестре станций — создайте станцию в админке или задайте `--station` |
| `time:…` | дата не разобрана — укажите `format` (например, `DD.MM.YYYY HH:mm`) |
| `futureTime` | время позже «сейчас + 1 ч» — проверьте часовой пояс |
| `value:PM25:abc` | нечисловое значение — добавьте маркер в `missingValues` или исправьте файл |
| `unitConversion:NO2:ppb` | для перевода объёмных единиц у вещества нет молярной массы (частицы в ppb невозможны) |
| `unknownPollutant:…` | название вещества не найдено — добавьте в `pollutantAliases` |
| `unit:кг` | неизвестная единица в столбце единиц (допустимы µg/m³, mg/m³, ppb, ppm и их написания) |

После импорта проверьте данные на странице станции (периоды 30 дней / год) и в админке
«Измерения → просмотр»; значения вне диапазона попадают в очередь QC.
