# Независимое ревью критичного кода перед первым деплоем

Дата: 19.10.2026. Объём: аутентификация и авторизация, приём данных станций, безопасность веба,
доменная логика, эксплуатация (миграции, seed, compose, образы). Метод: чтение кода, целевые тесты на
найденные дефекты (vitest / Playwright), исправление в коде; спорные места — в разделе «Оставлено как есть».
Код семи недельных сессий до этого проверялся только их авторами.

Серьёзность: **высокая** — потеря данных, обход контроля доступа или неработоспособность в продакшене;
**средняя** — уязвимость с ограниченным эффектом или ошибка, видимая пользователю; **низкая** — усиление
защиты, устойчивость, качество.

## 2. Проверено без замечаний

- **Аутентификация**: better-auth — самостоятельная регистрация закрыта, пароль ≥ 10, `trustedOrigins` = адрес портала,
  cookie httpOnly/SameSite/Secure; сессия после пароля при включённой 2FA не создаётся до TOTP; смена роли, бан, сброс
  пароля и 2FA завершают сессии пользователя; последний активный администратор защищён от понижения/бана/удаления;
  `locale` пользователя недоступен для изменения через `update-user` (`input: false`). Матрица прав `@meteo/core/authz`
  применяется во всех 30 страницах админки и во всех изменяющих server actions (проверка сессии из БД, zod, аудит).
- **IDOR**: действия над источниками станций проверяют принадлежность `stationId`; публичные API и страницы фильтруют
  `is_public` и выведенные станции (`/api/v1/stations`, `/stations/{slug}/measurements`, `index/current`,
  `exceedances`, границы, SILAM‑точки, sitemap, форма подписки); правила уведомлений оцениваются только по публичным
  станциям.
- **Приём данных**: ключ станции — 24 случайных байта, в БД SHA‑256, поиск по хэшу (тайминг‑атаки неприменимы);
  ≤ 1000 записей, время из будущего (> 1 ч) и старше 730 дней отклоняются, NaN/Infinity невозможны через JSON и
  отсекаются zod, `averagingMin` 1–1440, конверсия единиц только при известной молярной массе; upsert по ключу
  идемпотентен, решения оператора (`qc_locked`) не перезаписываются; SQL только параметризованный (Drizzle, `sql`
  с параметрами). Агент станции: ключ из конфига или переменной окружения, повторы с экспоненциальной задержкой,
  401/403 фатальны, 413 делит пакет.
- **Веб**: CSP с nonce и `strict-dynamic`, `frame-ancestors 'none'` + `X-Frame-Options: DENY` вне `/embed`,
  `object-src 'none'`, `base-uri 'self'`; загрузки — тип по сигнатуре, UUID‑имена, путь по регулярному выражению,
  `sandbox` CSP, PDF как вложение; Markdown‑рендерер экранирует всё, что не разметка, URL только `http(s)`, `mailto`
  и относительные без `//` и `/\`, управляющие символы удаляются; письма экранируют подстановки, ссылки с токенами
  подтверждения/отписки — стандартный double opt‑in; RSS экранирует все поля.
- **Доменная логика**: интервалы индекса полуоткрытые `[lo, hi)`, пустые данные → уровень 0, деление на ноль
  исключено (`limit <= 0` пропускается, `hazardClass` с запасным показателем); QC устойчив к константным рядам
  (MAD = 0) и коротким выборкам; окна индекса — часовые бакеты UTC, сутки/месяц в `Asia/Dushanbe`; устаревание 6 ч;
  события превышений — одно активное на правило и станцию, cooldown соблюдается, письма дедуплицируются по событию и
  подписчику; CAP: публикуются только `Actual` + `Alert/Update`, `Update/Cancel` помечают предыдущие по `references`
  (в обе стороны по времени прихода), `expires` фильтрует действующие, Test/Exercise только в админке; SILAM: NaN и
  отрицательные значения отбрасываются, пустая сетка — ошибка загрузки, а не нулевые слои.
- **Эксплуатация**: миграции 0000–0006 применены на пустой базе `timescale/timescaledb-ha:pg17` (отдельный контейнер,
  порт 5433): 7 записей в журнале миграций, гипертаблица `measurements`, три continuous aggregates, триггер append‑only
  аудита; повторный `migrate` — без изменений; `seed` дважды — идемпотентен (6 веществ, 12 ПДК, 3 шкалы, 60 порогов,
  5 рекомендаций, 5 регионов и регионов предупреждений, 8 точек прогноза, 9 правил QC, 3 рубрики, 1 администратор).
  Worker завершается штатно по SIGTERM (закрывает очередь, соединения, health‑сервер). Образы web и worker собираются
  (см. §4). `.env.example` покрывает все переменные web/worker/compose.

## 5. Рекомендации перед деплоем

1. Задать в `.env` на сервере `STATION_SOURCES_KEY` (`openssl rand -base64 32`) до создания первого источника станции —
   смена ключа позже потребует повторного ввода паролей источников.
2. После первого запуска проверить: `curl -s https://<домен>/api/healthz` → `redis: "ok"`; письмо «Проверка почты» из
   «Настроек» действительно доходит (теперь `SMTP_URL` попадает в worker); `/admin` → дашборд → интеграции CAP/SmartMet
   показывают адреса из `.env`.
3. При подключении SFTP‑источников заполнять отпечаток ключа хоста.
4. Повторить `pnpm audit --prod` и Trivy на итоговом коммите (CI); при обновлении Caddy оставить `header_up X-Forwarded-For`.
