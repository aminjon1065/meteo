# ADR-004: Интеграция SILAM — THREDDS NCSS → worker (TS) → PNG‑слои и точечные ряды

**Status:** Proposed · **Date:** 2026-10-16

## Context
FMI публикует SILAM (глобальный домен 20 км, 121 ч, 7 веществ) на THREDDS (OPeNDAP, NetCDF Subset Service, HTTP) и как открытые данные на S3 (CC BY 4.0). WMS на THREDDS не подтверждён. Нужны: слой на карте с ползунком времени и точечные прогнозы для станций/городов. Бюджет модуля — 800 USD.

## Decision
Задача `silam-sync` в worker: NCSS‑запрос по bbox Таджикистана в NetCDF‑3 (несколько МБ), чтение в TypeScript (`netcdfjs`), билинейная интерполяция в точки, генерация PNG‑кадров с палитрой уровней (`sharp`), публикация через статику; метаданные и точечные ряды — в Postgres. Источник, bbox, список веществ — конфигурация.

## Options Considered
| Вариант | Complexity | Cost | Качество карты | Итог |
|---|---|---|---|---|
| A. NCSS → TS worker → PNG + точки (выбрано) | Med | Низкая | Достаточное при 20 км | Полный контроль, один язык |
| B. NetCDF → SmartMet Server (nctoqd) → WMS + timeseries | Med–High | Зависит от доступа к серверу FMI | Отличное | Зависимость от конфигурации SmartMet, которую ставит FMI |
| C. Python‑сервис (xarray) → PNG + точки | Med | Низкая | Достаточное | Второй язык в стеке |
| D. Клиентское чтение OPeNDAP в браузере | High | 0 | Плохое на медленной сети | Отклонено |

## Trade-off Analysis
B даёт лучшие карты, но делает M5 заложником M2 и чужой конфигурации. A укладывается в бюджет и срок, а при появлении SmartMet WMS слой переключается конфигурацией.

## Consequences
- Проще: детерминированный ежедневный пайплайн, кэшируемые PNG.
- Сложнее: своя палитра/легенда; NetCDF‑4 без NCSS потребует варианта C.
