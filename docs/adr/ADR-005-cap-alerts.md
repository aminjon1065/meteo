# ADR-005: CAP‑предупреждения — собственный рендер вместо web‑компонента FMI

**Status:** Proposed · **Date:** 2026-10-16

## Context
SmartMet Alert выдаёт CAP 1.2. FMI публикует `@fmidev/smartmet-alert-client` — web‑компонент (Vue 3) с визуализацией предупреждений по регионам и дням, ориентированный на Финляндию. Нам нужны 3 языка, единый дизайн, отображение на общей карте MapLibre, API и виджеты для meteo.tj.

## Decision
Парсить CAP в нормализованную модель (`cap_alerts`, `cap_alert_info`, `cap_alert_areas`) и рендерить сами: список по дням/регионам, слой на MapLibre, баннеры, виджет. Web‑компонент FMI — в спайке недели 1 как кандидат для страницы `/warnings`, если его кастомизация под регионы Таджикистана и tg окажется дешёвой.

## Options Considered
| Вариант | Complexity | Cost | UX‑консистентность | Итог |
|---|---|---|---|---|
| A. Собственный рендер (выбрано) | Med | Средняя | Полная | Контроль языков, карты, API |
| B. `@fmidev/smartmet-alert-client` | Low–Med | Низкая, если подходит | Частичная (Vue‑островок, свой стиль) | Зависимость от конфигурации под Финляндию |
| C. Оба: компонент FMI на `/warnings`, свой слой на карте | Med | Средняя | Смешанная | Два пути отображения одних данных |

## Consequences
- Проще: единый источник правды в БД, API для meteo.tj, архив предупреждений.
- Сложнее: самостоятельно реализовать семантику Update/Cancel/expires и геокоды.

## Action Items
1. [ ] Получить образцы CAP от SmartMet Alert Таджикистана (D3) и список регионов.
2. [ ] Спайк web‑компонента: параметры, подмена геометрий.
