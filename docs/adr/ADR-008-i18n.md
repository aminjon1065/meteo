# ADR-008: Локализация — next-intl, tg по умолчанию, контент в jsonb и таблицах переводов

**Status:** Accepted (16.10.2026) · **Date:** 2026-10-16

## Context
Три языка с полной локализацией UI и контента; SEO‑URL; таджикский — государственный язык.

## Decision
next-intl с сегментом `[locale]`, `localePrefix: 'as-needed'` (tg без префикса, `/ru`, `/en`), `hreflang`. Справочники — `jsonb {tg,ru,en}` с фолбэком tg→ru→en на уровне `core/i18n.pick()`. CMS — таблицы `*_translations` с отдельными slug. Сообщения UI — JSON на язык, типизированные ключи, CI‑проверка полноты.

## Options Considered
| Вариант | Итог |
|---|---|
| A. next-intl (выбрано) | Нативная интеграция с App Router, форматирование Intl, маршрутизация |
| B. i18next/react-i18next | Богатая экосистема, но маршрутизация и SSR‑интеграция сложнее |
| C. Lingui | Хороший экстрактор, меньше примеров для App Router |

Автоопределение языка по Accept‑Language/cookie отключено (`localeDetection: false`): `/` всегда отдаёт таджикскую версию, переключение — явное, URL стабильны для SEO и ссылок с meteo.tj.

## Consequences
- Проще: один механизм на UI и контент, предсказуемые URL.
- Сложнее: дисциплина перевода при каждом релизе (DoD включает 3 языка).
