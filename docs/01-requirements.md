# 01. Требования: разбор ТЗ

## 1. Контекст

- **Заказчик:** Агентство по гидрометеорологии (Таджикгидромет). Сейчас у Агентства есть сайт **meteo.tj** (трёхъязычный TJ/RU/EN, текстовые прогнозы по регионам, SVG‑иконки погоды, по разметке похож на Laravel‑приложение). Пункты меню «Метео алерт» и «Харитаи обу ҳаво» уже существуют.
- **Донор/плательщик:** FMI. В рамках FINTAJ (фаза 3) FMI уже: поставил оборудование для мониторинга воздуха в Душанбе (2024), разработал и адаптировал **SmartMet Alert** под Таджикистан (мастер‑класс 01.2025, семинар по установке 01.2026), обучил специалистов **SmartMet** (08.2026). То есть серверы SmartMet/SmartMet Alert устанавливает FMI совместно с Агентством; наша задача по модулям 2, 3, 5 — **интеграция и вывод данных на сайт**, а не разработка этих систем.
- **Исполнитель:** ООО «ВОЯЖ». Обязанности по контракту, влияющие на процесс: еженедельные отчёты Заказчику о ходе работ (п. 4), изменения ТЗ только письменно (п. 4), техподдержка 6 месяцев после Акта (п. 4), Заказчик предоставляет доступы и документацию (п. 1.4, 5.1) и обеспечивает работоспособность своих IT‑решений (п. 5.3).
- **Сроки:** большинство модулей — 10 недель от подписания (06.10.2026 → ~15.12.2026); модули 4 и 6 — 3 недели. Контракт до 31.12.2026.

## 2. Модули ТЗ → требования

### M1. Мониторинг качества атмосферного воздуха (10 нед., 2 900 USD)

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR1.1 | Оперативная и историческая визуализация измерений с национальных станций | На карте и странице станции видны текущие значения и история; «последнее обновление» отображается всегда |
| FR1.2 | Расчёт национального индекса загрязнения для PM2.5, PM10, NO2, SO2, CO, O3; опционально — AQI по рекомендациям ВОЗ. **Методика подтверждена ежедневными бюллетенями Агентства (19.10.2026):** кратность ПДКс.с. по среднесуточной и ПДКм.р. по максимальной разовой концентрации, суммация NO₂+SO₂ (сумма кратностей), случаи ВЗ (≥ 10 ПДКм.р.) и ЭВЗ (≥ 50 ПДКм.р.); таблица ПДК бюллетеня; дополнительно измеряются NO, формальдегид, фенол, HF, взвешенные частицы (пыль), CO₂ (ppm), ЛОС (ppb) | Движок индекса табличный: шкалы и пороги редактируются в админке; покрыт unit‑тестами на граничных значениях; шкала «Кратность ПДК» (`RATIO_TO_LIMIT`) с суммацией и признаками ВЗ/ЭВЗ на странице станции и в API |
| FR1.3 | Пятиуровневая цветовая шкала PM2.5 (зелёный/жёлтый/оранжевый/красный/фиолетовый) с мед. рекомендациями по уровням | Уровень показывается цветом + текстом + иконкой (не только цветом); рекомендации редактируются в админке |
| FR1.4 | Исторические графики по станции с агрегацией по часам/дням/месяцам; выгрузка CSV | График переключает агрегацию; CSV содержит время (UTC и локальное), значение, единицы, флаг качества |
| FR1.5 | Уведомления (портал + e‑mail) при превышении настраиваемых порогов/индексов | Правила настраиваются в админке; письма уходят подписчикам; есть защита от спама (cooldown) |
| FR1.6 | Панель медицинских консультаций: пояснения для каждого уровня, отдельно для общего населения и уязвимых групп (дети, беременные и кормящие, пожилые, хронические респираторные и сердечно‑сосудистые заболевания) | Контент трёхъязычный, по группам, доступен со страницы станции и отдельной страницей |

## 3. Нефункциональные требования (выведены из ТЗ и контекста)

| Область | Требование |
|---|---|
| Языки | tg (по умолчанию), ru, en. Цепочка фолбэков контента: tg → ru → en. Часовой пояс отображения Asia/Dushanbe (UTC+5), хранение в UTC |
| Производительность | Публичные страницы — SSR с кэшем; LCP ≤ 2,5 с на мобильном 4G; JS главной ≤ 250 КБ gzip; API p95 ≤ 300 мс для рядов станции за год (за счёт предрассчитанных агрегатов) |

| Доступность | WCAG 2.1 AA; уровни загрязнения передаются цветом + подписью + иконкой; клавиатурная навигация; текстовые альтернативы карте и графикам |
| Надёжность | Деградация без падения: при недоступности SmartMet / CAP / SILAM / SMTP портал показывает последние данные с пометкой «устарело»; целевая доступность 99,5 % |

| Безопасность | HTTPS/HSTS, CSP, RBAC, аудит, rate limiting, 2FA для администраторов, валидация всех входов, резервные копии с шифрованием, сканирование зависимостей и образов |

| SEO | Локализованные URL (`/`, `/ru/…`, `/en/…`), hreflang, sitemap, OG/Twitter‑карточки, JSON‑LD для новостей |

## 5. Открытые вопросы к Заказчику (зафиксировать письменно)

1. Портал живёт на отдельном поддомене (например, `portal.meteo.tj`) со ссылками и виджетами на meteo.tj — или внутри meteo.tj? Рекомендуем поддомен.
2. Что считать «национальным индексом»: комплексный ИЗА (по среднемесячным), оперативный индекс «кратность ПДК» или обе шкалы? Рекомендуем обе + 5‑уровневую оперативную шкалу (по образцу финского индекса) как основную для публики.
3. Станции: сколько, какие вещества, автоматический поток или ручной ввод проб? Будут ли исторические данные для загрузки?
4. Регионы предупреждений SmartMet Alert: совпадают ли с областями/районами?
5. Нужны ли push‑уведомления / Telegram‑бот (не в ТЗ, возможное расширение)?
6. Кто администрирует SmartMet Server / SmartMet Alert после сдачи (для раздела runbook)?
7. Срок M6 «3 недели» — подтвердить трактовку как «бета‑версия к 3‑й неделе, финал к 10‑й».
