# Агент станции Метеопортала

English version: [README.md](README.md).

Программа из одного файла на Node.js для станционного компьютера. Следит за папкой экспорта
вендорского ПО (файлы CSV/TSV), разбирает новые строки по описанию колонок и отправляет их на портал:
`POST /api/v1/ingest/{станция}` с ключом API станции. Ведёт журнал отправленного (строки не уходят
повторно), повторяет запросы при сбоях сети и работает как служба (Планировщик заданий Windows, NSSM
или systemd). Подходит для любого экспорта: формат файла описывается в `config.json`.

Тот же парсер встроен в worker портала (задача `station-pull`, источники SFTP/FTP/HTTP в карточке
станции), поэтому описание колонок, составленное для агента, можно без изменений вставить в панель
администратора.

## Требования

- Node.js 22 LTS (Windows: <https://nodejs.org> → установщик LTS или `winget install OpenJS.NodeJS.LTS`;
  Debian/Ubuntu: `apt install nodejs` из репозитория NodeSource 22.x). Других зависимостей нет — агент один файл.
- Исходящий HTTPS (TCP 443) со станционного компьютера на адрес портала. Входящие порты не нужны.
- Ключ API станции: панель администратора → «Станции» → карточка станции → «Ключ API станции» →
  «Сгенерировать ключ» (ключ показывается один раз; на портале хранится только его хэш).

## Установка

1. Скопируйте `station-agent.mjs` и один из конфигов из `examples/` в папку, например `C:\meteo-agent\`
   или `/opt/meteo-station-agent/`. Переименуйте конфиг в `config.json`.
2. Заполните `config.json`: `portalUrl`, `stationCode`, `watchDir`, `mapping`. Ключ укажите либо в
   `apiKey` (тогда ограничьте доступ к файлу учётной записью службы), либо в переменной окружения,
   имя которой записано в `apiKeyEnv`.
3. Проверьте папку и формат самого свежего файла:

   ```bash
   node station-agent.mjs --config config.json --check
   ```

4. Посмотрите, что будет отправлено, ничего не отправляя:

   ```bash
   node station-agent.mjs --config config.json --dry-run
   ```

5. Отправьте один раз (`--once`) и посмотрите результат в карточке станции (блок «Автоматический приём данных»):

   ```bash
   node station-agent.mjs --config config.json --once
   ```

Коды выхода: 0 — успех, 1 — ошибка конфига или папки, 2 — портал отклонил ключ станции, 3 — портал
недоступен после повторов.

## Параметры конфига

| Поле | Назначение | По умолчанию |
|---|---|---|
| `portalUrl` | адрес портала, например `https://portal.meteo.tj` | обязательно |
| `stationCode` | код станции из реестра (`DU-01`) | обязательно |
| `apiKey` / `apiKeyEnv` | ключ API станции или имя переменной окружения с ключом | одно из двух |
| `watchDir` | папка экспорта (абсолютный путь или относительно `config.json`) | обязательно |
| `filePattern` | маска файлов: `*.csv`, `DU-01_*.txt`, `????-??-??.csv` | `*.csv` |
| `recursive` | искать и во вложенных папках | `false` |
| `mapping` | формат файла (см. ниже) | обязательно |
| `pollIntervalSec` | период опроса в режиме службы; `0` — один проход и выход | `60` |
| `batchSize` | записей в одном запросе (не больше 1000) | `500` |
| `timeoutMs`, `retries` | таймаут запроса и число повторов (сеть, 5xx, 429) | `30000`, `5` |
| `maxFileMb` | файлы крупнее пропускаются | `20` |
| `lookbackDays` | при первом запуске отправляются только файлы, изменённые за N дней; `0` — все | `7` |
| `settleSec` | файлы, изменённые менее N секунд назад, откладываются до следующего прохода (их ещё пишет ПО) | `5` |
| `stateFile` | журнал отправленных строк | `station-agent.state.json` рядом с конфигом |
| `logFile`, `logMaxMb` | файл лога с ротацией (копия `.1`) | только stdout, `5` |

### Описание формата (`mapping`)

| Поле | Назначение |
|---|---|
| `delimiter` | `;`, `,`, `tab`, `pipe`; без значения — определяется по строке заголовка |
| `encoding` | `utf-8` (по умолчанию), `windows-1251`, `utf-16le` … |
| `headerRow` | номер строки заголовка (1); `0` — заголовка нет, колонки задаются индексами с 0 |
| `skipRows` | сколько строк после заголовка пропустить (единицы, описания) |
| `commentPrefix` | строки, начинающиеся с него, пропускаются (`#`) |
| `layout` | `wide` — столбец на вещество; `long` — вещество / значение / единица в каждой строке |
| `time` | `{ "column", "format", "timezone" }` или `{ "dateColumn", "timeColumn", "format", "timeFormat", "defaultTime", "timezone" }`. Токены формата: `YYYY MM DD HH mm ss` (`DD.MM.YYYY HH:mm`); без формата распознаются ISO 8601, `DD.MM.YYYY HH:mm` и `YYYY-MM-DD HH:mm`. `timezone`: `Asia/Dushanbe` (по умолчанию), `UTC` или `+05:00` |
| `pollutants` (wide) | `{ "PM2.5": { "column": "PM2.5 (мкг/м3)", "unit": "µg/m³", "scale": 1, "flagColumn": "PM2.5 Статус" } }` — ключ: код вещества или любой синоним (`pm2.5`, `Ozone`, `NO₂`, `Диоксид серы` …) |
| `pollutantColumn`, `valueColumn`, `unitColumn`, `flagColumn`, `defaultUnit` (long) | колонки длинного формата |
| `pollutantAliases` | дополнительные синонимы: `{ "Ch1": "PM25", "Ozone 1h": "O3" }` |
| `missingValues` | строки «нет значения»: `["", "-", "-999", "NaN"]` |
| `statusColumn`, `invalidStatuses`, `validStatuses` | колонка статуса строки; строки с недопустимым статусом уходят с флагом `invalid` (сохраняются на портале, в индекс не попадают) |
| `averagingMin` | период осреднения строк, мин (по умолчанию — настройка станции) |

Единицы: если у колонки нет `unit`, портал берёт единицу ввода станции для этого вещества (карточка
станции → «Измеряемые вещества»). Значения вида `<5` (ниже предела обнаружения) принимаются. Портал
переводит ppb/ppm/мг/м³ в единицу вещества, применяет правило диапазона контроля качества и
пересчитывает индекс.

Примеры конфигов в `examples/`: `config.wide-semicolon.json` (экспорт с русской локалью, `;`,
`DD.MM.YYYY HH:mm`), `config.long-format.json` (строки «параметр / значение / единица», UTC),
`config.tsv-iso-utc.json` (TSV со строкой единиц, колонками статусов, ppb), `config.split-date-time.json`
(дата и время в разных колонках, windows-1251, титульная строка над заголовком). Образцы файлов —
в `examples/data/`.

## Как устроена отправка

- Каждый проход составляет список файлов по маске. Файл обрабатывается, если он новый или изменились
  размер/дата. Если файл только дописывался (та же первая строка, размер больше), уходят только строки
  после последней отправленной; если переписан — файл отправляется целиком. Портал хранит значения по
  ключу «время + вещество + осреднение», поэтому повторная отправка никогда не создаёт дублей.
- Записи уходят пакетами (`batchSize`). Портал отвечает числом принятых и отклонённых записей и причиной
  по каждой (`unknownPollutant:X`, `pollutantNotConfigured:PM10`, `time`, `unit:x`, `futureTime` …);
  агент пишет причины в лог с номерами строк файла.
- Сетевые ошибки, 5xx и 429 повторяются с нарастающей задержкой (2, 4, 8 … с, учитывается `Retry-After`);
  после `retries` попыток проход прерывается и возобновляется при следующем опросе. 401/403 — неверный
  ключ или код станции, исправьте конфиг. 413 — пакет делится пополам.
- Журнал (`stateFile`) записывается после каждого пакета; удалите его, чтобы отправить заново всё за
  `lookbackDays`.

## Запуск как служба

### Windows — Планировщик заданий (рекомендуется, `--once` каждые 5 минут)

Запустите `service\install-task.cmd` от имени администратора из папки агента или создайте задачу вручную:

```bat
schtasks /Create /F /SC MINUTE /MO 5 /TN "Meteoportal station agent" /RU SYSTEM /RL LIMITED ^
  /TR "\"C:\Program Files\nodejs\node.exe\" \"C:\meteo-agent\station-agent.mjs\" --config \"C:\meteo-agent\config.json\" --once"
```

В конфиге укажите `pollIntervalSec: 0` (или оставьте `--once`). Чтобы передавать ключ через окружение
задачи, запишите его в `apiKeyEnv` и задайте системную переменную (`setx /M METEO_STATION_API_KEY mst_…`).

### Windows — NSSM (постоянная служба)

Скачайте NSSM (<https://nssm.cc>), положите `nssm.exe` рядом с агентом и запустите `service\nssm-install.cmd`
от имени администратора. Служба перезапускает агент при сбое, лог — в `service-stdout.log`.
`nssm edit MeteoStationAgent` открывает настройки, `nssm remove MeteoStationAgent confirm` удаляет службу.

### Linux — systemd

```bash
sudo useradd -r -s /usr/sbin/nologin meteo-agent
sudo mkdir -p /opt/meteo-station-agent && sudo cp station-agent.mjs config.json /opt/meteo-station-agent/
echo 'METEO_STATION_API_KEY=mst_…' | sudo tee /opt/meteo-station-agent/agent.env && sudo chmod 600 /opt/meteo-station-agent/agent.env
sudo chown -R meteo-agent:meteo-agent /opt/meteo-station-agent
sudo cp service/meteo-station-agent.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now meteo-station-agent
journalctl -u meteo-station-agent -f
```

Учётная запись службы должна читать папку экспорта (`ReadWritePaths` в unit-файле — только папка
агента; чтение папки экспорта при `ProtectSystem=strict` разрешено, запись в неё не нужна).

## Если что-то не так

| Признак | Что делать |
|---|---|
| `Портал отклонил ключ станции (401)` | неверный `stationCode` или ключ; создайте новый ключ в карточке станции |
| `(403 station_inactive)` | станция приостановлена или выведена из эксплуатации на портале |
| записи отклонены с `pollutantNotConfigured:PM10` | отметьте вещество в карточке станции («Измеряемые вещества») |
| `unknownPollutant:TEMP` | колонка — не загрязнитель: уберите её из `mapping.pollutants` или добавьте `pollutantAliases` |
| `time:…` | неверный `time.format`; запустите `--check` и сравните с образцами строк |
| `Портал недоступен` | проверьте доступ по HTTPS со станции (прокси, межсетевой экран); агент повторяет попытки сам |
| ничего не отправляется | `--dry-run`; проверьте `filePattern`, `lookbackDays` (первый запуск) и `settleSec` |
| самоподписанный сертификат портала | добавьте CA в системное хранилище или запускайте с `NODE_EXTRA_CA_CERTS=/path/ca.pem` |

Безопасность: не храните ключ в общих папках; агенту нужен только исходящий HTTPS; портал ограничивает
`/api/v1/ingest` 60 запросами в минуту на станцию (агент отправляет не больше одного запроса на пакет).

## Разработка

Исходник — `src/agent.ts`, парсер — `@meteo/core/station-feed`. `pnpm --filter @meteo/station-agent build`
собирает всё в `station-agent.mjs` (esbuild, файл хранится в репозитории);
`pnpm --filter @meteo/station-agent test` — модульные тесты (журнал, повторы, пакеты).
