# Административные границы Таджикистана

Загрузчик `infra/data/load-boundaries.ts` заполняет таблицы `regions` (geom, centroid) и `districts`
(docs/02-architecture.md §5.1). Официальных границ от Агентства пока нет (зависимость D9 в
docs/01-requirements.md), поэтому используются открытые данные.

## Источники

| Что | Источник | Лицензия | Примечание |
|---|---|---|---|
| Коды и названия (admin1, admin2) | [OCHA COD-AB Tajikistan](https://data.humdata.org/dataset/cod-ab-tjk), файл `tajikistan-administrative-division_v2.1.xlsx` (Агентство по статистике, ОКАТО, январь 2017) | CC BY-IGO | Геометрии в COD-AB для Таджикистана **нет**: OCHA ROCCA ведёт её для внутренних нужд и не публикует. Таблица выверена и сохранена в `tjk-admin-units.json` (P-code = код ОКАТО, названия tg/ru/en, алиасы для сопоставления, прежние названия). |
| Геометрия (по умолчанию) | [GADM 4.1](https://gadm.org), `gadm41_TJK_1.json`, `gadm41_TJK_2.json` (июль 2022) | **Только некоммерческое использование**; распространение и коммерческое использование — с разрешения GADM ([лицензия](https://gadm.org/license.html)) | Требование задачи как фолбэк при недоступности COD-AB. Для публичного портала госоргана с открытым API это распространение данных — лицензию нужно согласовать или перейти на geoBoundaries. 5 полигонов admin1, 59 admin2 (≈6,8 тыс. вершин). |
| Геометрия (альтернатива) | [geoBoundaries](https://www.geoboundaries.org) 6.0 gbOpen TJK ADM1/ADM2 (данные OpenStreetMap, 2017; сборка 2023‑12, коммит `9469f09`) | ODbL 1.0 (© OpenStreetMap contributors) | Лицензия совместима с уже используемой картой Protomaps/OSM (ADR‑003), детализация выше (≈20 тыс. вершин). Включается `--source=geoboundaries`. |

Российские сервисы не используются.

## Запуск

```bash
pnpm --filter @meteo/db boundaries
```

Параметры (флаги или переменные окружения):

| Флаг | Переменная | По умолчанию | Назначение |
|---|---|---|---|
| `--source=gadm\|geoboundaries` | `BOUNDARIES_SOURCE` | `gadm` | источник геометрии |
| `--tolerance=<градусы>` | `BOUNDARIES_TOLERANCE` | `0.002` (≈200 м) | допуск `ST_SimplifyPreserveTopology`; `0` — без упрощения |
| `--dry-run` | — | выкл. | скачать, сопоставить и показать таблицу соответствий без записи в БД |
| `--refresh` | — | выкл. | скачать файлы заново (иначе берутся из кэша) |
| — | `BOUNDARIES_TMP` | `$TMPDIR/meteo-boundaries` | папка кэша загрузок |
| — | `DATABASE_URL` | из корневого `.env` | подключение к PostgreSQL/PostGIS |

Скрипт идемпотентен: upsert по `regions.code` и `districts.code` в одной транзакции. У `regions`
обновляются только `geom` и `centroid` (названия ведёт seed/админка), у `districts` — `region_id`,
`name`, `geom`. Единицы без полигона в источнике (четыре района Душанбе и города областного
подчинения, территория которых в GADM/OSM входит в полигон одноимённого района) записываются с
`geom = NULL`. Записи `districts`, которых нет в таксономии, не удаляются — о них выводится предупреждение.

Что делает скрипт:

1. скачивает GeoJSON admin1/admin2 во временную папку (кэш между запусками);
2. сопоставляет admin1 с кодами областей `DU`, `RRP`, `SU`, `KT`, `GB` по алиасам из `tjk-admin-units.json`;
3. сопоставляет admin2 с единицами таксономии по нормализованным названиям (включая прежние названия);
   если полигон не сопоставлен — завершается с ошибкой и списком, что добавить в `aliases`;
4. записывает геометрию (`ST_MakeValid` → `ST_SimplifyPreserveTopology` → `ST_Multi`), центроиды
   (`ST_Centroid`, если он внутри полигона, иначе `ST_PointOnSurface`), названия на трёх языках;
5. печатает проверки: число областей с геометрией, число районов, невалидные геометрии, районы вне своей
   области, площади областей.

Названия: `tg` — «Ноҳияи …» / «Шаҳри …», `ru` — полная форма («Айнинский район», «Город Худжанд»),
`en` — латинское имя из таблицы или транслитерация таджикского (`transliterate` из `@meteo/core`) плюс
`district`/`city`.

## Обновление и официальные данные

- Таксономия COD-AB датирована январём 2017 г.; переименования 2018 г. (Курган-Тюбе → Бохтар,
  Сарбанд → Левакант, Бохтарский район → Кушониён) внесены вручную и помечены полем `note`.
  Коды ОКАТО сохранены. Список нужно подтвердить у Агентства (D9).
- Когда Агентство передаст официальные shapefile/GeoJSON, достаточно добавить в скрипт ещё один
  `BoundarySource` (адаптер свойств → название/область) — сопоставление и запись не меняются.
- Публичный API: `GET /api/v1/regions` (apps/web) отдаёт области как GeoJSON FeatureCollection с кэшем 1 час.
